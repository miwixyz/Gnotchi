## Verhalten

- **Schalter** „Claude Code in der Notch“ (Reiter Mitteilungen, ab Werk **aus**). An → Gnotchi trägt seine Hooks ein
  (Sicherungskopie vorher). Aus → entfernt genau diese. Geht das Eintragen nicht sicher (siehe G35), zeigt Gnotchi den
  Grund und den Eintrag zum Einfügen von Hand.
- **Sitzung** = `session_id`. Angezeigt: Projektname (letzter Teil von `cwd`), Status, gekürzte Antwort.
  - Eingabe → **arbeitet** · `PermissionRequest` → **wartet auf Erlaubnis** + Werkzeug + Kurzfassung (Bash: Befehl
    gekürzt; Datei-Werkzeuge: nur Dateiname) · `PostToolUse` → wieder arbeitet · `Stop` → **fertig** + Antwort (erste
    ~2 Zeilen) · `SessionEnd` → weg. Fertige Sitzungen verschwinden nach 30 Min, stumme „arbeitet“ nach 30 Min.
- **Live-Aktivität `claude`** in Rotation/Leiste, solange eine Sitzung arbeitet oder wartet. Klein: Symbol + Status
  (wartet = Gelb, arbeitet = Orange, ohne Notch zusätzlich Projektname). Groß: bis 3 Sitzungen untereinander
  (Projekt, Status, 2 Zeilen Antwort). Band: als eigene Seite rechts.
- **„Fertig“-Meldung:** kurze Insel wie ein Hinweis (3 s): „Claude fertig · Projekt“ + erste Zeile der Antwort.
- **Klick** auf eine Sitzung → das Programm der Sitzung kommt nach vorn (Terminal, Obsidian, Desktop-App). Den
  einzelnen Tab/Chat kann Gnotchi nicht wählen.

## Aufbau

- **Hook-Programm „Gnotchi Claude“** (`dev.mwlr.gnotchi.claude`, eigenes Paket in `Gnotchi.app/Contents/Helpers/`,
  Developer ID, Hardened Runtime, keine Entitlements). Läuft nur kurz je Ereignis: liest stdin (≤ 1 MB), baut daraus
  **eine** bereinigte Nachricht, sucht über die Eltern-Prozesse die erste App (Kennung + PID), verbindet sich mit
  `~/Library/Application Support/Gnotchi/claude.sock`, **prüft den Server** (Audit-Token gegen Gnotchis Developer ID),
  wartet auf `ok`, schickt, endet. Läuft Gnotchi nicht → endet sofort still (Exit 0).
- **Hook-Eintrag** je Ereignis (`UserPromptSubmit`, `PermissionRequest`, `PostToolUse`, `Stop`, `SessionEnd`):
  `{"type":"command","command":"test -x '<Pfad>' && '<Pfad>' || true","async":true}` – erkennbar am Pfadteil
  `Gnotchi Claude.app`.
- **Gnotchi** (`ClaudeLink`): `PeerSocketServer` auf `claude.sock` mit Anforderung `dev.mwlr.gnotchi.claude`,
  `coalesce: false`; Modell `ActivityModel+Claude`.
- **Nachricht** `{"v":1,"claude":{"session","event","project","app","pid","tool","detail","text"}}` – `ClaudeWire`
  (eine Datei in beiden Zielen).

## Sicherheitsentwurf

### G34 – Claude-Hook-Weg: nur Status und gekürzter Text, beidseitig geprüft (neu, 0.9.0)

- **Hook-Programm prüft Gnotchi**, bevor es sendet (die Antwort von Claude kann Vault-Inhalte enthalten – ein
  falscher „Gnotchi“ bekäme sie sonst). **Gnotchi prüft das Hook-Programm** (sonst könnte jeder Prozess falsche
  „fertig“/„wartet“-Meldungen einblenden).
- **Datensparsam im Hook-Programm:** gesendet werden nur Sitzungs-Kennung (UUID-Zeichen), Ereignis, Projektname
  (letzter Pfadteil), App-Kennung + PID, Werkzeugname, Kurzfassung (Bash-Befehl ≤ 120 Zeichen, sonst nur Dateiname),
  Antwort ≤ 300 Zeichen. **Nie** `transcript_path`, Prompt-Text, Dateiinhalte, Umgebungsvariablen.
- **Schema auf beiden Seiten** (strikt wie G29), Texte bereinigt (G21), Anzeige nur `Text(verbatim:)`.
- **Nie gespeichert, nie protokolliert** (Protokoll: Ereignis-Art, Zahl der Sitzungen).
- **Nur lesen:** Das Hook-Programm gibt **nie** eine Entscheidung zurück (keine Ausgabe auf stdout, Exit 0) – auch
  bei `PermissionRequest`. Damit kann Gnotchi keine Werkzeuge erlauben/ablehnen (Michael: „nur anzeigen“).
- **Klick:** nur `NSRunningApplication(processIdentifier:)` der gemeldeten PID **und** gleiche Kennung → `activate`.
  Startet nichts, öffnet keine Pfade.

### G35 – `~/.claude/settings.json`: nur eigene Einträge, byte-genau oder gar nicht (neu, 0.9.0)

- Lesen → in eine **reihenfolgetreue** Struktur → zurückschreiben muss die Originaldatei **byte-gleich** ergeben;
  sonst wird nichts geschrieben (Grund + Eintrag zum Einfügen von Hand).
- Nur Einträge, deren Befehl `Gnotchi Claude.app` enthält, werden angelegt/ersetzt/entfernt; alles andere bleibt.
- Vorher Sicherung `settings.json.gnotchi-backup` (0600), dann **atomar** schreiben (temporär + umbenennen), Rechte
  wie vorher. Datei ist ein Link/fehlt/größer als 1 MB → nichts tun, Hinweis.
- Pfad im Eintrag = Gnotchis eigener Paketpfad; bei jedem Start geprüft und bei Abweichung (verschoben, Testkopie)
  nachgezogen.

| STRIDE | Bedrohung | Antwort |
|---|---|---|
| S | Fremdprozess als „Gnotchi“ liest Claudes Antworten mit | G34: Hook-Programm prüft Server vor dem Senden |
| S | Fremdprozess blendet falsche „wartet auf Erlaubnis“-Meldung ein (Social Engineering) | G34: Gnotchi prüft Client; Notch hat keinen Erlauben-Knopf |
| T | Gnotchi beschädigt Michaels Claude-Einstellungen | G35: byte-gleich oder gar nicht, nur eigene Einträge, Sicherung, atomar |
| R | – | kein Entscheid aus der Notch |
| I | Antwort-/Befehlstexte im Protokoll, in Dateien | G34: nur Arbeitsspeicher, gekürzt, nie protokolliert |
| D | Hook bremst Claude | `async: true`; ohne Gnotchi sofort Exit 0 |
| D | Viele Ereignisse gleichzeitig | Server 1 Verbindung zur Zeit (eine neue ersetzt die alte) → selten verlorenes Ereignis, Zeitablauf räumt auf (hingenommen) |
| E | Hook-Programm als Hebel | keine Entitlements, keine Kindprozesse, kein Netz, liest nur stdin |
