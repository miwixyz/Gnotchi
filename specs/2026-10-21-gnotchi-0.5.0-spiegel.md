# Gnotchi 0.5.0 – Spiegel (Kamera-Vorschau) – Spezifikation + Sicherheitsentwurf G27

Stand 2026-10-21, 19:25. Michael 18:50: „Vor einem neuen Release wäre das Spiegelfeature noch ganz cool“,
19:22 „OK weiter“. Fahrplan-Stufe 0.8.0 vorgezogen in 0.5.0.

## Verhalten

- In der Symbolleiste der großen Insel steht ganz rechts bei den Symbolen ein Kamera-Symbol „Spiegel“.
  Ein Klick zeigt groß das Bild der Kamera, **gespiegelt** wie ein Spiegel, abgerundet.
- Die Kamera läuft **nur**, solange der Spiegel groß sichtbar ist. Maus verlässt die Insel / anderes Symbol
  gewählt → Kamera sofort aus. Kein Hintergrundbetrieb, kein Zeitlimit nötig.
- Die große Insel wird dafür höher (Bild 16:9 über die ganze Breite).
- Erste Nutzung: macOS fragt nach der Kamera-Freigabe (ausgelöst durch den Klick, nie beim Start).
  Verweigert → Karte „Kamera nicht erlaubt“ mit Knopf „Einstellungen“ (öffnet Datenschutz → Kamera).
- Schalter „Spiegel in der Notch“ (`mirror`), ab Werk an. Aus → kein Symbol, Kamera nie angefasst.
- Kamera: die Standard-Kamera von macOS (`AVCaptureDevice.default(for: .video)`).

## Sicherheitsentwurf G27

**Daten:** Kamerabild = höchst privat. **Nie gespeichert, nie verarbeitet, nie gesendet**: Das Bild geht
nur von `AVCaptureSession` direkt in eine `AVCaptureVideoPreviewLayer` (kein `VideoDataOutput`, kein
Foto-Ausgang, kein Puffer im eigenen Code). Protokoll nur „Spiegel an/aus/verweigert/keine Kamera“.

**Berechtigung:** `com.apple.security.device.camera` (Hardened Runtime) + `NSCameraUsageDescription`.
Positivliste G12 ändert sich: App **genau** `automation.apple-events` + `device.camera`; eingebetteter Code
weiterhin keine (`release.sh`/`entitlement-gate.sh` angepasst).

| STRIDE | Bedrohung | Antwort |
|---|---|---|
| I | Kamera läuft unbemerkt weiter | Läuft nur bei sichtbarem Spiegel; `onDisappear` und Moduswechsel stoppen die Sitzung; grüne Kamera-LED von macOS; Gnotchis eigener Kamera-Punkt (PrivacyMonitor) zeigt es zusätzlich |
| I | Bild landet auf der Platte / im Protokoll | Kein Ausgang außer der Vorschau-Ebene; kein Bildschirmfoto-Code; Protokoll ohne Inhalt |
| E | Kindprozess `/usr/bin/perl` (Medien-Adapter) erbt Gnotchis Kamera-Freigabe (macOS rechnet ihn Gnotchi zu, gemessen 18.10.) | G2: Skript und Adapter-Framework werden vor jedem Start auf Unversehrtheit geprüft (Bundle-Signatur); der Adapter enthält keinen Kamera-Code. Restrisiko hingenommen: wer Gnotchis signiertes Bundle unbemerkt ändern kann, hat ohnehin mehr. Gemessen wird: Freigabe gilt für `dev.mwlr.gnotchi` |
| E | Eingeschleuster Code in Gnotchi nutzt die Freigabe | Hardened Runtime ohne Ausnahmen (keine `disable-library-validation`, G12) |
| S | Fremde App löst Gnotchis Spiegel aus | Nur ein Klick in der Insel startet ihn; keine Nachricht, kein Socket, kein URL-Schema dafür |
| D | Kamera belegt, wenn ein Call startet | macOS teilt die Kamera zwischen Apps; Spiegel schließt beim Verlassen der Insel ohnehin |
| R | – | Keine Aktion mit Folgen |
