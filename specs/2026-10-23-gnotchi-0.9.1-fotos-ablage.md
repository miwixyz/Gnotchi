# Gnotchi 0.9.1 – Fotos aus der Fotos-App in die Ablage (Spezifikation + Sicherheitsentwurf G32 Ergänzung)

Stand 2026-10-23. Meldung Michael 23.10.: „Bilder aus der Fotos App können nicht in die Ablage gezogen werden.“

**Entscheidungen Michael 23.10.:** Fotos werden als **Kopie in Gnotchis eigenen Ordner** übernommen; **Entfernen aus
der Ablage löscht diese Kopie** (nie Originale, nie andere Dateien) · direkt als **0.9.1** veröffentlichen.

## Gemessen 23.10. (vor dem Bau)

- **Was Fotos beim Ziehen anbietet** (Messprogramm auf `NSPasteboard(name: .drag)`, ein Element): Dateiversprechen
  (`com.apple.NSFilePromiseItemMetaData`, `promised-file-name`, `promised-file-content-type`), `public.jpeg` **und**
  `public.file-url`. Die Ablage klappt also auf (DragWatcher sieht `public.file-url`) – bestätigt von Michael.
- **Wohin `public.file-url` zeigt:** auf eine **Vorschaudatei in der Mediathek**
  (`~/Pictures/Photos Library.photoslibrary/resources/derivatives/…_1_105_c.jpeg`), nicht auf das Original.
- **Gnotchi beim Loslassen:** fragt `public.file-url` und `NSFilePromiseItemMetaData` ab, protokolliert
  **„0 abgelegt“**, Hinweis „Schon in der Ablage“ (falsch). Warum die Vorschau verworfen wird, ist nicht endgültig
  belegt (vermutet: Mediathek für Gnotchi gesperrt) – für die Lösung egal: Selbst angenommen wäre es eine verkleinerte
  Vorschau, die Fotos jederzeit löschen darf.
- Finder-Element zum Vergleich: nur `public.file-url` + `com.apple.finder.node`, kein Versprechen.

## Verhalten

- **Element mit Dateiversprechen** → Gnotchi lässt die liefernde App die Datei in einen frischen Unterordner seines
  Kopien-Ordners schreiben (`NSFilePromiseReceiver`), legt die Kopie in die Ablage. Der mitgelieferte Datei-Verweis
  dieses Elements wird ignoriert (bei Fotos nur die Vorschau).
- **Element ohne Versprechen** (Finder) → unverändert: Verweis (Lesezeichen), keine Kopie.
- **Entfernen / Leeren / Rausziehen-und-angekommen** → liegt die Datei noch im Kopien-Ordner, wird ihr Unterordner
  gelöscht. Hat der Finder sie beim Rausziehen verschoben, liegt sie draußen und bleibt unangetastet.
- **Hinweis** sagt die Wahrheit: „n abgelegt“ · „Ablage voll“ · „Schon in der Ablage“ (nur wenn wirklich alles schon
  drin war) · sonst **„Nicht abgelegt“**.
- Nicht im Umfang: Ziehen, das **nur** ein Versprechen ohne `public.file-url` trägt (z. B. Mail-Anhänge), öffnet die
  Ablage weiterhin nicht – ungemessen, eigener Schritt.

## Sicherheitsentwurf (rafter-secure-design: ingestion, data-storage, threat-modeling)

| Frage | Entscheidung |
|---|---|
| Vertrauensgrenze | Andere App (gleicher Nutzer) → Gnotchi. Sie bestimmt Dateiname und Inhalt der Kopie. |
| Speicherort, Namensschema | `~/Library/Application Support/Gnotchi/Ablage-Kopien/<UUID>/<Name der App>`. Ordner 0700, über `prepareDirectory` (lstat, eigener Nutzer, kein Link). Den Pfad setzt AppKit aus unserem UUID-Ordner + Name zusammen; der Name kann nur innerhalb des frischen UUID-Ordners landen. |
| Prüfung nach dem Schreiben | Ergebnis-URL standardisiert + Links aufgelöst muss **direkt** im eigenen UUID-Ordner liegen, `lstat` ≠ Link, Eigentümer = wir. Sonst UUID-Ordner löschen, nicht ablegen. |
| Löschen (Retention) | Nur Unterordner **direkt** im Kopien-Ordner, mit UUID-Namen, ermittelt aus dem aufgelösten Lesezeichen. Nie außerhalb (Lesezeichen folgen verschobenen Dateien → Prefix-Prüfung zum Löschzeitpunkt). Verwaiste UUID-Ordner (kein Eintrag verweist hinein) werden beim Start und nach Entfernen/Leeren gelöscht. |
| Größe / Anzahl | Anzahl: höchstens so viele Versprechen wie Plätze frei (≤ 50). Größe: keine Grenze (eigene App des Nutzers, Videos legitim groß) – hingenommen. Zeitlimit 120 s je Ablegen, danach gilt es als gescheitert, UUID-Ordner weg. |
| Ausführen / Öffnen | Unverändert nichts (kein `NSWorkspace.open`). Die Kopie wird nur weitergereicht. |
| Datenschutz | Fotos sind privat: Ordner 0700, Kopie verschwindet mit dem Eintrag. Protokoll nur Zahlen, nie Namen/Pfade. |
| Berechtigungen | Keine neue (kein Fotos-Zugriff, keine Mediathek-Freigabe – die App schreibt selbst). |
| Restrisiko (hingenommen) | Eine App kann eine präparierte Datei versprechen – sie liegt dann als Kopie in Gnotchis Ordner und wird nie gestartet (wie bisher bei Verweisen). |
